# 功能实现与闭环审计（2026-10-14）

## 结论与审计口径

当前项目已经具备较完整的核心 CAD 自动化链路和广泛的功能代码，但尚不能认定“全部功能完成、全部入口可靠、交付完全闭环”。最大的缺口不是继续增加工具数量，而是统一真实执行入口、错误语义、运行状态、验证证据和发布版本。

本次检查当前工作区源码、运行时工具注册、安装包位置、测试代码及选定离线测试。未启动或关闭 SOLIDWORKS，未操作用户模型，未运行真实 CAD 集成测试，未操作 CAXA。历史对话中用户提供过 DXF 导入及拉伸真实测试通过的日志；这只能证明当时该场景通过，不能替代当前版本全功能验收。

必须区分五层：工具存在 → 调用真实适配器 → 模型操作符合预期 → 保存/重开/下游软件消费成功 → 同版本安装包在其他电脑复现。255 个工具既不是 255 个独立 CAD 能力，也不代表覆盖 SOLIDWORKS 全部 API。

## 架构与现有优势

主链路为：外部 MCP 客户端或本地面板 → FastMCP 注册表 → 工具函数 → 工作流/适配器 → Windows COM → SOLIDWORKS → 文件及结果。

推荐的结构化路径是 `tools/mvp.py` → `application/mvp_workflow.py` → `contracts/mvp.py`、`application/sessions.py`、`artifacts/store.py` → 真实适配器。它已经提供：

- 类型化参数、统一操作结果、错误码和建议。
- 会话与文档归属校验；面、边、尺寸、配合、BOM 等服务端生成引用及修订检查，避免智能体猜本地化名称。
- 操作时重新激活对应文档；共享 COM 操作锁及草图状态检查。
- 输入/输出目录约束；保存和导出后检查产物存在，返回大小与 SHA-256。
- 常规 stdio 仅附加已有 SOLIDWORKS；显式面板启动入口独立；退出服务不直接退出 SOLIDWORKS。

这些是本项目已有的可靠性基础，但旧工具、UI 和不同进程不完全共享上述约束。

## 关键闭环断点与优先级

### P0：生产入口不能返回模拟成功

`tools/drawing.py` 以下旧入口直接构造 success，而没有执行真实工程图操作：`create_drawing_view`、`add_dimension`、`add_note`、`create_section_view`、`create_detail_view`、`update_sheet_format`、`auto_dimension_view`、`check_drawing_standards`。

`tools/analysis.py` 的 `analyze_geometry` 固定返回 “No issues found”，`get_material_properties` 固定返回普通碳钢物性。`tools/automation.py` 的 `automation_stop_macro_recording` 固定返回时间、动作数和文件路径；其他若干函数在缺少适配器方法时回退到模拟成功，VBA 回退内容还有 TODO。

后果：客户端能看见“成功”，但文档、分析或文件没有产生对应变化。建议迁移至真实结构化实现；没有真实能力的入口返回明确 unsupported，或只在显式 mock 模式提供示例。不能把上述所有模拟注释都计作真实模式必然触发，条件回退需单独确认适配器绑定。

验收：真实模式所有成功必须可回读或检查产物；不支持操作明确失败；旧新入口行为一致。

### P0：面板把调用完成与业务成功混在一起

`ui/panel_runtime.py::execute` 在 `call_tool` 未抛异常时统一返回 `ok: true`；没有检查结构化结果里的 `status: failed/error`。面板据 `ok` 显示“完成”。因此即使工具业务失败，也可能展示为成功。必须统一协议成功、业务成功与部分成功语义。

### P1：运行状态、启动恢复与并发

- `CircuitBreakerAdapter.start_solidworks` 成功后调用 `_record_success`，但后者不处理 OPEN 状态；已打开的熔断器可能在启动成功后继续拒绝操作。
- PanelRuntime 依赖缓存的 `server.state.is_connected` 决定是否重新连接；手动关闭 SOLIDWORKS 后存在状态陈旧风险。连接操作发生在执行锁之外，应检查并发 attach。
- stdio 启动互斥只覆盖该启动脚本；面板独立进程与 stdio 不共享工作流锁/状态。一个 SOLIDWORKS 实例需要明确单一操作协调者。
- 快捷方式发现使用名称匹配，需要验证目标确实为 SLDWORKS.exe；COM 尚未注册、启动超时后重试需要防重复启动。

验收：运行中附加、未运行显式启动、手工关闭后恢复、启动超时重试、熔断恢复、双客户端均不能产生错误实例或操作错文档。

### P1：内嵌插件与面板交付

`addin/SolidWorksMcpAddin/SwAddin.cs` 使用 `ISwAddin`，项目仅引用 sldworks/swconst，应补查 swpublished 接口引用；WinForms/System.Drawing 构建引用也需核对。本机未发现 dotnet/msbuild，不能宣称已构建成功。SDK 项目默认产物带 net472 子目录，文档里的 DLL 路径需与实际构建结果一致。

面板尚不解析 JSON Schema `$ref`，复杂输入主要依赖手写 JSON，不能认定所有工具都有完善图形化参数编辑。`run-panel.ps1` 用可能初始化 COM 的健康接口加 2 秒超时判断服务是否存在，存在误判后重复尝试启动风险。

### P1：发布版本一致性

- 本机安装包 253，当前源码 255；已有 wheel/tar 时间为 2026-07-29，ZIP 为 2026-08-22，不能当作当前源码的新发布。
- 安装脚本执行 `pip install .`，而 FastAPI 在可选 ui/test 依赖内；基础 MCP 安装不能保证面板运行依赖齐全。
- sdist 白名单未包含 `run-mcp-stdio.ps1`、外部安装脚本和 stdio 配置样例，源码包不等于完整外部分发包。
- README 顶部要求 stdio 脚本，但 VS Code/LM Studio 示例仍使用人工调试 `run-mcp.ps1`；需统一配置。

验收：发行版本及构建标识可查询；ZIP、wheel 和源码一致；新机器安装、枚举工具、建模、保存重开与卸载均有记录。

### P1：验证体系不能把 error 当成功覆盖

全工具冒烟调用旧工具 `tool.fn(payload)`，绕过 FastMCP 参数反序列化，日志中大量出现 dict 无属性错误。因此其报告既不是协议调用验收，也不是所有真实工具都失败的证据。测试主要检查不抛异常、返回对象和 status 存在；返回 error 仍可能通过。

本次还发现 `test_adapters.py` 中 `test_adapter_factory_registry` 被嵌套进另一个测试函数，不再被 pytest 独立收集。目录快照文件不存在时，若干目录校验会跳过。旧 API 覆盖文档中的约 20% 等统计及待实现列表过时，不能作为当前完成比例。

### P2：完整性扩展

补充弧/圆完整求交与轮廓嵌套、CAXA 尺寸与实体读取往返、复杂装配依赖文件复制/移交、长期会话恢复、完整高级装配/分析能力。按实际场景定义支持矩阵，不以“增加了一个 COM 方法”代替闭环。

## 本轮已落实的收口修复（2026-10-15）

更新后的准确状态见 [1.0.1 更新与验证记录](../user-guide/release-1.0.1.md)。下文原始审计问题用于保留发现依据，不代表全部仍未修复。

- 面板执行结果现在同时检查 FastMCP `is_error` 与业务 `status`；`failed`、`error`、`unsupported` 不再显示为 `ok: true`。
- 熔断器在显式启动成功后会关闭此前的 OPEN 状态，避免 SOLIDWORKS 已恢复但后续工具仍被拒绝。
- 旧工程图、几何分析、材料物性和自动化入口在没有真实适配器绑定时返回 `unsupported`，不再返回虚假的尺寸、物性、时间或文件路径。原本断言模拟成功的测试已同步验证 `unsupported`。
- 面板串行化连接并按真实健康结果清除陈旧状态；版本、客户端配置、安装依赖及分发文件清单已修正；Task Pane 引用与 DLL 文档路径已补齐。
- 选定离线回归最终 339 项通过，真实模型及 C# 插件验收仍待完成。

这三项修复没有替代真实 SOLIDWORKS 验收，也没有把旧入口变成真实 COM 实现；它们的作用是让失败和未实现状态可被外部智能体正确识别。

## 本次验证结果

### 后续 1.0.2 收口（2026-10-15）

详见 [1.0.2 更新记录](../user-guide/release-1.0.2.md)。真实适配器已增加跨进程连接生命周期占用锁；已有进程但 COM 未注册、启动超时后重试均避免重复启动；快捷方式验证实际目标；取消操作清理 COM 后才释放占用。新增客户端协议建模/产物测试。选定回归 424 项、新增协议场景 1 项通过。

跨进程策略是拒绝第二个操作进程，不是共享 RPC 调度；真实 CAD/CAXA、异机安装及 C# 插件验收仍未完成。以下原审计数据保留用于追溯。

选定范围：application、MVP 工具、DXF 导入、CAXA DXF 规范化、panel runtime/router、all-endpoints harness。

- 初跑：104 passed、16 skipped、2 failed；两个失败都是固定目录 `tests/.generated/solidworks_integration` 写报告被拒绝。
- 经批准沙箱外只重跑这两项模拟测试：2 passed。合计选定 122 项：106 通过、16 跳过；真实 COM 场景未运行。
- 工具冒烟报告共 255 行：57 success、117 succeeded、64 error、17 failed。**174 个成功结果、81 个失败结果不是功能完成率**：部分是输入/前置条件或直接函数调用问题，部分是模拟返回。
- 当前源码工具目录实测 255 个唯一名称；普通安装包导入实测 253。

## 建议收口顺序与最终验收标准

1. 清理生产模式模拟成功及旧新入口差异，修正面板业务成功判断。
2. 收口实例生命周期、连接状态、熔断恢复与跨进程调度。
3. 改成通过真正 MCP 协议调用的场景测试；按功能建立“输入→操作→回读→保存→重开→输出消费”证据表。
4. 构建并验收 Task Pane；补齐 UI 依赖和图形输入边界。
5. 统一版本、文档、发布包，完成异机安装及 CAXA 2015 消费验收。
6. 再扩展尚未支持的高级功能。

优先验收六条链路：零件建模修改保存重开；装配插入配合干涉及依赖移交；钣金法兰/K 因子/展开；工程图视图标注/BOM 保存重开；CAXA 基础实体导出读取；DXF 校验导入拉伸后尺寸/体积回读。每条同时包含无效输入、错误选择、失败恢复和不丢用户文件的检查。

只有全部声明支持的场景有真实结果证据、没有模拟成功冒充真实执行、外部发布可复现，才可称为该支持范围内完整闭环。当前阶段的准确定位是：**核心链路已建立，广泛功能已有代码，可靠性与交付收口尚未完成。**
