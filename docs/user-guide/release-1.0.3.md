# 1.0.3 执行层收口

本版修复智能路由递归、跨文档缓存串数据、配置别名覆盖和鉴权未接入调用链的问题。

- MCP 运行时只走实际 COM 后端；VBA 生成包装准确返回 `route=com`、`vba_executed=false`。可信宏执行保留独立入口。
- 默认仅缓存 API 文档发现；模型、尺寸、特征、配置、工程图分析均实时查询，避免手工编辑和切换文档造成陈旧结果。
- 配置优先级为：显式正式字段 > 显式旧别名 > 默认值。
- FastMCP 工具调用中间件执行鉴权和限流；支持 `api_key`/`api_keys` 配置的多个密钥。HTTP 客户端使用 `Authorization: Bearer <key>`；程序内和 stdio 调用可在工具参数顶层携带 `api_key`（中间件会在参数校验前移除）。启用严格模式但未配置密钥时拒绝调用。面板启用鉴权后同样需要凭据。
- 限流按每个服务器实例共享预算执行，不接受客户端自报的身份来重置预算。默认 60 次/分钟，批量建模可显式提高 `rate_limit_per_minute` 或关闭 `enable_rate_limiting`。日志中的凭据脱敏。
- 原生适配器通过 STA 工作线程执行，连接、建模、保存、断开保持同一线程。旧装配保存辅助操作也经该线程执行。
- 已提交的 COM 操作不能安全强行中断。取消会等待原生操作结束再释放工作流锁；不能把客户端超时理解成“未执行”。
- 面板超时返回 `status=pending`、`operation_id`、`retry_safe=false`；通过 `GET /api/panel/operations/{operation_id}` 查询最终结果。面板自动轮询，未完成前拒绝新的面板操作。历史完成结果最多保留 200 条、有效期一小时，重启后不持久化。

## 2026-10-18 审查修复

- MCP 中间件对完整工具调用串行化，覆盖旧工具、会话工具和 DXF 多步导入，避免激活文档与后续操作之间插入另一工具调用。多个独立请求仍不构成事务；多客户端应使用带文档标识的会话工具。
- 面板使用共享 MCP 服务时，重连保留原服务绑定及会话，不创建竞争服务；自有服务仍可停止后重建。
- 明确开启真实 SolidWorks 测试后，连接失败判为失败，不再以跳过掩盖权限或 COM 故障。
- 安装脚本强制重装项目本体，再检查依赖，避免同版本旧 wheel 留存。源码启动仍推荐使用 `run-mcp-stdio.ps1` 或 `run-panel.ps1`。源码修改不会自动更新既有 ZIP/wheel，分发前需重新构建。

## 安装更新

源码运行需重启 MCP 服务。已有 wheel 安装需安装 1.0.3，再重启外部客户端。旧 1.0.2 ZIP/wheel 不包含本次修复。

本轮验证使用离线适配器、FastMCP 实际协议调用和线程行为测试；不代表真实 SolidWorks/CAXA、Task Pane 插件及异机安装已全部验收。真实验收应继续检查：创建→修改→保存→关闭文件→重开回读，以及钣金、装配、工程图、CAXA 往返场景。
