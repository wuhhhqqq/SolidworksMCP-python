# 1.0.2 会话与启动收口更新

本版本在 1.0.1 基础上补充真实适配器的进程占用保护和启动防重，不增加工具数量。

- 真实 COM 连接持有当前 Windows 用户的操作系统文件锁。同进程适配器共享占用；另一 MCP 进程返回 `SW_AUTOMATION_PROCESS_BUSY`，不启动新的 SOLIDWORKS。最后一个适配器断开或进程退出后释放锁。锁标记文件保留，不要手动删除正在使用的标记。
- 显式启动先附加 COM；COM 未注册时检查当前登录会话的 `SLDWORKS.exe`，已有进程则等待注册，不再次启动。进程检查失败时拒绝启动。
- 新启动进程立即记录，超时重试仍检查原进程。此保护不结束 SOLIDWORKS，也不关闭用户文档。
- 配置的启动路径必须指向 `SLDWORKS.exe`，快捷方式实际目标也必须存在且为该程序。配置无效时明确失败，不静默改用其他版本。
- 连接或启动被取消时先清理 COM，再释放占用，避免留下未受保护的连接。
- 新增 FastMCP 客户端协议测试，验证结构化参数与结果、草图状态错误、建模、原生保存及 STL 导出的文件大小/哈希；模拟 STEP 导出未生成文件时必须返回失败。

## 部署与并发边界

一个 Windows 用户同时使用一个真实 MCP 操作进程。面板与独立 stdio 服务不是跨进程共享状态的 RPC 代理；同时连接时第二个进程会被拒绝。需要切换时，先断开原服务。使用已有面板/API 时，请按该服务支持的调用方式接入；该 API 不等于通用远程 MCP HTTP 端点。

普通 stdio 启动脚本仍仅附加已打开的 SOLIDWORKS；上述防重适用于显式启动接口。锁保护仅对采用此版本的真实适配器进程有效，不能约束人工操作或旧版本服务。

更新前停止对应 MCP 服务，解压完整新版，运行 `INSTALL-外部用户.ps1`，再启动客户端。ZIP 包含源码、wheel、安装说明和启动/配置文件；不包含 Python、SOLIDWORKS、许可证及全量离线依赖。异机安装需要 Windows、64 位 Python 3.11+、SOLIDWORKS 和下载依赖的网络。
